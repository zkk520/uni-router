# 供应商多选与批量操作

## 目标

在供应商管理页面支持多选，并提供批量启用、停用、删除能力，减少管理员重复操作。

## 已确认事实

- 供应商页面位于 `web/src/components/modules/channel/index.tsx`，当前已有分页、搜索、状态/协议筛选、单条启停和单条删除。
- 后端供应商接口位于 `/api/v1/channel`，当前已有单条 `/enable` 和 `/delete/:id`。
- 用户要求同时支持跨页保留手动选择，以及按当前筛选条件选择全部结果。
- 批量操作需要新增后端批量接口，并支持部分成功。

## 需求

- 表格支持行多选、当前页全选、跨页保留手动选择。
- 支持选择当前筛选条件下的全部供应商，并允许从全选结果中排除当前页单行。
- 批量动作包括启用、停用、删除。
- 搜索词、状态筛选、协议筛选变化时清空当前选择，避免误操作旧筛选结果。
- 批量删除必须有确认弹窗，文案说明会删除供应商、密钥和统计数据。
- 后端批量接口接受 `ids` 或 `filter` 范围，返回成功和失败明细。

## 验收标准

- [ ] 手动勾选跨页保留，翻页后已选数量保持正确。
- [ ] 可选择当前筛选条件下全部结果，并能排除部分行。
- [ ] 批量启用/停用/删除调用 `/api/v1/channel/batch`，成功后刷新页面数据。
- [ ] 部分失败时前端展示成功/失败数量，并保留失败 ID 便于重试。
- [ ] 后端单测覆盖 ids、filter、部分失败、空结果场景。
- [ ] `go test ./...`、`cd web && pnpm run lint`、`cd web && pnpm run build` 通过，或明确记录未通过原因。

## 不在范围

- 不新增批量同步模型。
- 不变更路由引用清理策略。
- 不自动执行 `git push`。
